# Audience Segmentation — pages serve audiences, not everyone

## The core principle

**Not every page must appeal to every audience.** The instinct to make each
page speak to all visitors is the single most common content-strategy failure:
it produces pages that address no one clearly because they try to address
everyone. A page that speaks to everyone converts no one — the hiring manager,
the prospective client, and the peer are looking for different proof and want
different actions, and a page hedging toward all three gives each a diluted
version.

The strategy's job is the opposite: **segment pages to audiences.** Decide who
each page is for, write it for that reader, and let other pages carry the other
readers. A site is a set of doors, each labeled for who should walk through it —
not one lobby trying to greet everyone at once.

## Single-audience, single-CTA pages

Every page gets:

- **One primary audience** — the ONE reader (by ROLE) the page is written for.
  A page may be *readable* by others, but it is *optimized* for one. If you
  cannot name the one, the page has no job yet.
- **One primary call to action** — the single next step that reader should
  take. Two CTAs compete; the reader takes neither. Secondary links may exist,
  but one action is primary and unmissable.

When a real page genuinely must serve two audiences, that is usually a sign it
should be *two pages* — split it, and let the nav route each reader to theirs.
A shared page (home, about) still picks a primary audience and orients around
that reader's decision, offering the others a clearly-labeled path onward.

## Deriving a page inventory from audience answers

The page-to-audience map (outline #3) is *derived*, not guessed. Work from the
audience answers:

1. **List the audience segments** the brand actually wants (from the interview
   and sources). For each, capture — by ROLE, never name — who they are, the
   decision they arrived to make, the proof that would earn their trust, the
   objection that would bounce them, and the one action worth asking for.
2. **For each segment, ask: what is the minimum set of pages this reader needs
   to go from arrival to action?** A prospective-client segment might need
   a positioning page → a relevant proof piece → an inquiry page. A hiring
   segment might need an about page → a work catalog → a contact path. Write
   those pages down as that segment's journey.
3. **Merge the journeys into one inventory.** Where two segments need the same
   page (often the home page), that page still gets ONE primary audience — pick
   the one whose decision is highest-value or hardest-won — and routes the
   others onward. Where journeys need genuinely different content, that is
   separate pages, not one overloaded page.
4. **Tag each page** in the map: primary audience (one), primary CTA (one),
   status (`exists` / `revise` / `new` / `retire`). A page that survives the
   merge with no owning audience is a `retire` candidate — say so.
5. **Name the anti-audience.** Write down who the brand is explicitly NOT for.
   This is what lets pages be sharp; a page that is allowed to exclude can
   finally speak plainly to the reader it keeps.

## Guardrails

- If any page in the map lists "everyone", more than one primary audience, or
  more than one primary CTA, that is an open question for the interview, not a
  finished row.
- Segments are roles and needs, never named individuals — even when the user
  names a specific person they want to reach ("the hiring manager at a firm like
  X" is a role; the person's name never enters the report).
- Prefer fewer, sharper segments. Three well-served audiences beat seven
  half-served ones; each added segment is more pages to maintain and another
  chance to blur.
